# 0.0.4

本版以大量資料測試 24 種常見基本圖表，找出並修正效能問題；所有案例的畫布與
**Matplotlib 3.11.2 逐像素相同**。

```bash
python -m pip install matplotlib-rs==0.0.4   # 只會一併安裝 NumPy
```

## 修正內容

- **長條圖、直方圖**：`bar`／`barh`／`hist` 以每種樣式一個 prototype 批次複製 `Rectangle`
  與 Rust handle，資料範圍一次更新；仍回傳可各自修改的 `Rectangle`，有單位、逐根標籤或自訂 transform 時沿用原迴圈。
  `hist` 與 `hist2d` 對 65,536 筆以上、無權重的 float64 資料由 Rust 多執行緒執行 NumPy 的計數演算法，
  bin 邊界仍由 NumPy 計算，結果與 `numpy.histogram`／`numpy.histogram2d` 相同。
- **點陣化**：rasterizer 對只有水平與垂直邊的路徑逐列直接產生 cell；Agg 的 RGBA 混色以乘法取代三次整數除法
  （2³² 種輸入窮舉驗證），長段不透明底色另以查表混色。
- **path collection 平行化**：256 條以上、無裁切路徑與 hatch 的 `draw_path_collection` 與 `draw_quad_mesh`
  由多個執行緒點陣化、主執行緒依原順序渲染，混色順序不變；QuadMesh 不再為每格建立路徑陣列。
  `MPLRS_THREADS` 可指定執行緒數（`1` 為單執行緒）。
- **errorbar／stem**：修正 rust-numpy 對大量路徑 view 逐一 borrow 造成的平方複雜度。
- **折線建圖**：`_path` 模組直接讀取 NumPy 陣列，不再轉成 Python list。
- **等高線**：mpl2014 各層由多執行緒計算，並在 Rust 合併每層的路徑。
- **色彩對應與影像**：`Colormap._get_rgba_and_mask` 對 16,384 個以上的 float64／float32 值由 Rust 逐值執行
  NumPy 的步驟。`imshow` 縮小 3 倍以上（'rgba' 內插階段）時只計算每個像素的 lut 列號
  （一般的線性 `Normalize` 在同一次掃描中計算），重採樣器直接讀取已預先乘上 alpha 的 lut，
  不再建立 float64 RGBA 陣列（4000 × 4000 時為 512 MB）；影像重採樣的輸出列也分給多個執行緒。

## 測試

- 新增 `tests/unit/test_bar_batch.py`、`test_histogram.py`（一維 124 組、二維 78 組資料與 bins）、
  `test_colormap.py`（每個 colormap 邊界與特殊浮點值、遮罩、bytes、影像的各種 norm 與 alpha）。
- `test_resample.py` 新增大輸出（多執行緒）與 lut 索引重採樣，共 1,080 組與官方 `_image.resample` 逐位元相同。
- `tests/lowlevel/diff_path_collection.py` 以大量隨機 collection 與 quad mesh 比較官方 C++ Agg，逐位元組相同。
- `tests/compare` 新增 `imshow_large`（NaN／±inf、遮罩、float32、整數、LogNorm、TwoSlopeNorm、clip、
  vmin＝vmax、純量與陣列 alpha、半透明 lut、under／over／bad、各種內插與內插階段）。

本機結果（CPython 3.12、NumPy 2.3.5）：Rust 測試、全部單元與底層差異測試通過，
`tests/compare` 59／59 案例 PNG／SVG／PDF／EPS 與 Matplotlib 3.11.2 完全一致；基本圖表壓測 24 個案例 × 3 輪逐像素一致。

## 限制

- pie 的每個 wedge 與標籤仍逐一建立 Python 物件並同步到 Rust，500 片時比官方慢（0.8 倍）；
  violinplot 的成本在 Python／NumPy 的核密度估計，與官方相近。
- 平行化的效果取決於可用 CPU 核心數；量測主機為 4 vCPU。
